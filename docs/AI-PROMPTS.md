# 问内网 AI 的话术包（前后端对接用）

> 场景：后端在内网、不能外传。你要做的是——**把「前端契约」喂给内网的 AI，让它帮你把后端接上**。
> 下面每一段都可以整段复制粘贴，把 `<...>` 换成你的实际情况。

---

## 0. 先准备一份「上下文包」（每次提问都带上）

内网 AI 看不到这个仓库，所以每次对话先贴这三块，它能少猜一半：

| 顺序 | 贴什么 | 为什么 |
| --- | --- | --- |
| 1 | `shared/types.ts` 全文 | 唯一权威的类型定义 |
| 2 | `src/lib/api.ts` 全文 | 前端真正会发的请求（含超时时间） |
| 3 | `docs/BACKEND-INTEGRATION.md` 的 §3 + §4 | 接口清单与 SSE 规则 |

> 如果内网 AI 支持知识库/文件上传，把这三个文件传上去，后面就不必每次重复。

---

## 1. 先让它「读懂契约」，别急着写代码

```text
下面是一个 Electron 前端对后端的全部依赖（贴 shared/types.ts 与 src/lib/api.ts）。
请先不要写代码，只做三件事：
1) 用一张表列出前端实际调用的每个 HTTP 接口（方法、路径、请求体、响应体关键字段）；
2) 标出这些接口里哪些是「页面必须」，哪些是「可选能力」；
3) 指出 SSE 事件流里前端依赖的硬性约束（seq、终止事件、since 续传）。
输出用中文，表格优先，不要复述代码。
```

---

## 2. 生成后端骨架（按模块，一块一块来）

```text
按下面的契约，用 FastAPI 实现「项目与运行」这一组接口：
- GET/POST /api/projects
- GET/PATCH/DELETE /api/projects/{id}
- POST /api/projects/{id}/run
- GET /api/runs?projectId=
- GET /api/runs/{runId}
- POST /api/runs/{runId}/cancel

要求：
1) 字段名用前端契约里的驼峰（必要时用 Pydantic alias）；
2) POST /run 立刻返回 {runId, run}，不要阻塞等流水线跑完；
3) run 创建时就要带 steps 数组（7 个 pending 步骤）；
4) 业务逻辑用 <你的服务/仓储层> 的占位函数表示，我来补实现；
5) 时间戳统一毫秒。
先只给这一组，不要顺手把别的接口也写了。
```

> 依次再来三轮：`文档 / 差异 / 代码 / 提案`、`对话`、`Git 与 W3`。

## 3. 字段映射（最容易出错的一步）

```text
这是我的内部接口返回（贴脱敏后的真实 JSON）与前端契约里的 Project 定义。
请写纯函数 to_contract_project(row) 做映射，并满足：
- 时间字段秒转毫秒；
- status 枚举映射（内部取值：<贴出来>）；
- 缺失字段给合理默认值，不要抛异常；
- 输入输出都是 dict，便于单测。
另外给我 3 条 pytest 用例：正常行、缺字段行、状态未知行。
```

## 4. SSE 事件流（请它一次写对）

```text
按契约实现 GET /api/runs/{runId}/events?since=N，要求：
1) text/event-stream，每帧 data: {json}\n\n，结尾发 data: [DONE]；
2) seq 在同一个 run 内从 1 单调递增；
3) since=N 时先补发 seq>N 的历史事件，再转实时；
4) 事件同时落盘到 runs/{runId}.events.jsonl，进程重启后还能回放；
5) run.done / run.error 是终止事件，发出后关闭连接；
6) 响应头带 Cache-Control: no-cache 与 X-Accel-Buffering: no；
7) 用 ensure_ascii=False 保证中文不乱码。
给我 asyncio 版本（含一个可单测的 EventHub 类），不要用「轮询数据库」的实现。
```

## 5. 对话（流式 + 思考过程 + 工具调用）

```text
前端对话依赖这些事件：chat.reasoning（思考增量）、chat.delta（正文增量）、
chat.tool（工具调用）、chat.plan（任务清单）、chat.message（最终消息，必须发）。
请基于 <我们内部的模型网关> 实现流式对话，要求：
1) 把模型的 reasoning_content / reasoning 字段转成 chat.reasoning，不要把思考混进正文；
2) 正文逐块发 chat.delta，最后必发一条 chat.message（含 content，可选 proposal）；
3) 工具调用只允许只读（读文件/搜索）＋产出「改动建议」，不要直接写盘；
4) 网关不支持流式时退回非流式：仍按 36 字切片发 chat.delta，再发 chat.message；
5) 任何异常都要发 chat.message（带 error 字段）与 run.error，不要让前端一直转圈。
先给接口层与事件映射，模型调用用占位函数。
```

## 6. 鉴权怎么挂：让它只改一处

```text
我们的内网服务需要 <Bearer Token / 签名 / SSO Cookie>。
前端只会：调 /api/auth/w3/login 传用户名密码，之后所有请求默认不带凭证。
请给出方案：在 <FastAPI 中间件 / 依赖注入> 里统一注入凭证，并保证：
① 密码、token 绝不回传前端；
② /api/settings 只回 apiKeySet 这样的布尔；
③ 凭证过期时返回 401 + {"detail": "凭证已过期"}，前端会提示重新登录。
给我代码，并说明我怎么验证。
```

```text
不要直接给大改方案。
```

## 9. 让它帮你写契约测试（防止以后改坏）

```text
请为下面的接口写 pytest 契约测试（贴契约）：
- 每个接口断言状态码与关键字段；
- 对 SSE 写一个测试：启动 run → 读事件 → 断言 seq 单调递增、有 step.status、有终止事件；
- 用 httpx.AsyncClient + ASGITransport，不启真实端口；
- 测试数据用一个 fixture 造的最小项目。
```

## 10. 安全与合规（内网版的额外要求）

```text
请审查这段实现，从这四个角度找风险：
1) 前端可传入的路径参数是否会越权读写（应限制在项目工作目录内）；
2) 事件流里是否会泄露内部路径 / 凭证 / 主机名；
3) 日志是否会打印密码、token 或完整请求体；
4) 接口是否有速率与大小限制（比如 diff 接口被大仓库打爆）。
每条给「风险等级 + 最小修复」。
```

## 12. 一句话版（懒得写长 prompt 时）

```text
你是我的后端对接助手。前端契约见 shared/types.ts 与 src/lib/api.ts。
我需要实现 <模块名> 的以下接口：<路径列表>。

先给接口层骨架，业务逻辑用占位函数；不要改契约。
```

## 13. 提问时的三条纪律

1. **一次只问一块**：把 25 个接口一次性丢给 AI，它一定会写出「看起来对但细节全错」的代码；
2. **永远贴契约原文**，不要用「就是那个项目列表接口」这种指代；
3. **要求可验证输出**：curl 命令、pytest 用例、或契约检查器的预期结果——没有验证方式的产出，内网里没人敢合。
